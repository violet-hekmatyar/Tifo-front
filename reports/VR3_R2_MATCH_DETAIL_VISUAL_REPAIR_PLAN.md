## 2. 模块计划

### R2-M0：响应式基线

- 先修复 `11_width_360dp.png` 的残影/重叠和 `BOTTOM OVERFLOWED BY 1.3 PIXELS`。
- 修复 `12_font_140.png` 资讯卡 `BOTTOM OVERFLOWED BY 17 PIXELS`，确保头部、五 Tab、卡片标题和正文可读。
- 卡片高度不得依赖只能容纳 100% 字体的固定比例；需要固定视觉比例的图片与可变高度文字区分开布局。
- 为 360dp、412dp、100%/140% 字体补充 `tester.takeException()` 无异常断言，覆盖总览和五 Tab 切换。

完成门槛：两种适配状态均无黄黑条、重叠、残影、裁切和不可操作控件。

### R2-M1：总览骨架

- 复刻原型顺序和视觉层级：沉浸式比赛头部 → 五 Tab → 最新资讯 → 大幅主内容卡 → 简要统计 → 中轴事件时间线。
- 最新资讯仅取真实关联内容：顶部使用紧凑双列卡，另选一条有封面的真实内容作为大幅主卡；点击均进入内容详情，不伪造视频播放或时长。
- 将事件改为主客分列的中轴时间线，分钟位于中轴，真实进球、换人、黄/红牌和半场节点具备不同视觉标识。
- 对齐原型的边距、圆角、标题位置和信息密度，不继续使用整页等权通用卡堆叠。

完成门槛：总览顶部与中后段截图均可直接对应原型区块，真实内容和事件交互保持有效。

### R2-M2：阵容球场

- 使用一张连续纵向球场承载双方首发，不再以两个短半场形成拥挤拼接效果。
- 仍使用真实 `fieldX/fieldY`，在显示层做安全边距和同排防碰撞；不得硬编码球员或修改阵容数据。
- 放大球员头像、姓名/号码和评分标识；真实事件存在时显示牌类、进球或换人标记，缺失时不伪造。
- 保证两队各 11 个节点清晰可点，球场后继续展示教练、替补、伤停空态和图例。

完成门槛：常规宽度、360dp 和 140% 字体下均无重叠或溢出，球员姓名与关键标记可读。

### R2-M3：统计页

- 建立稳定的类型到“进攻 / 组织 / 防守”映射，并将三个分组渲染为独立圆角卡。
- 每行只显示中文指标、主客数值和成对比较条；界面不得出现 `OFFSIDES`、`PASS_ACCURACY` 等原始枚举。
- 未知类型使用中文安全兜底或独立“其他”组，不丢失数值，也不直接展示后端枚举。
- 球员统计保留在球队统计之后，现有筛选和分页行为不变。

完成门槛：三类卡片的顺序、层级和紧凑度与原型一致，真实 API 数值完整。

### R2-M4：评分三态

- 评分列表改为原型式球员视觉卡：放大真实头像，突出姓名、星级/主评分、官方或用户评分与人数；无真实热评时不编造热评。
- 评分详情改为全屏或接近全屏的页面态，保留沉浸式比赛头部和清晰返回；依次呈现球员主视觉、单场关键统计、我的评分、球迷分布、真实评论/空态及固定底部输入入口。
- 评分输入改为真正的大型底部层，不得在 BottomSheet 内嵌 `AlertDialog`；包含球员信息、五颗星与 1～10 分映射、大文本输入和发布按钮。
- 正式输入截图必须聚焦文本框并显示系统软键盘；只展示真实可用操作，不增加无行为的附件或社交按钮。
- 评分提交、覆盖、撤销、评论提交及失败隔离逻辑保持不变。

完成门槛：列表、详情、输入三张截图均与各自原型具备相同页面层级和主体比例，且原有真实交互通过。
