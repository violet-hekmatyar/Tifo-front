## 1. 唯一目标与边界

只修复 VR4 复核确认的总览重复、主队状态、数据选择/分组和榜单全部页问题，并用同一最终 APK 完成 7 张球队详情原型的正式视觉证据。不得进入球员详情 VR5，不修改后端、数据库、API 契约、P1 数据或 VR1-VR3 页面；不得因取图困难改用 fixture APK。

## 2. R1-M1：头部主队状态与总览去重

### 主队按钮

- 头部按钮只表达“加为主队/已是主队”，不得再根据登录态调用球队关注接口。
- 未登录点击进入现有登录流程；已登录且不是主队时调用既有 `setMainTeam(teamId)`。
- 成功后刷新/回读现有用户摘要中的 `mainTeam`，只有回读确认目标球队时显示“已是主队”并禁用重复提交；失败保持原状态并可重试。
- 为未登录跳转、成功回读、重复点击保护和失败恢复补定向测试；删除/改写球队页上仍断言关注切换的旧测试。

### 总览

- 删除遗留的通用基础信息 Card、第二个下一场、最近比赛、第二套最新动态和旧 `topScorers/topAssists` 纵向榜单。
- 总览只保留一次且严格按原型顺序：下一场比赛 → 赛事排名 → 双列最新资讯 → 并列队内榜单 → 基本信息 → 球队荣誉。
- 若 `leaderboards` 为空，可从真实 `topScorers/topAssists` 映射成同一视觉组件作为降级，但两套来源不得同时展示。
- 增加 Widget 断言：下一场、最新资讯、队内榜单、基本信息各只出现一次，模块纵向顺序正确。

完成门槛：标准宽度总览首屏和长页无重复内容，所有入口使用真实 ID 可达。

## 3. R1-M2：数据页、选择层和榜单全部

### 数据与选择层

- 将真实指标按进攻、组织、防守、纪律等类别分组；仅展示已有字段，不伪造指标。视觉采用原型的分组白卡、行式数值/必要进度表达，不再把全部字段塞入一个“进攻”双列网格。
- 总计/场均继续使用同一真实统计来源；场均安全处理零场次，百分比等比例字段不得再次除以场次。
- 选择层按真实 `seasonName` 分组赛事，提供标题、关闭按钮和当前项标记；切换后页面标题必须显示实际选项，不得固定取 `options.first`。
- 测试覆盖赛季分组、当前项、切换标签、关闭和快速切换后旧响应不回写。

### 榜单全部

- 改为与原型一致的全屏页面态，包含酒红顶部、明确返回、球队名、真实赛季选择、榜单指标选择和完整真实球员排行。
- 指标来自响应中的 `leaderboards`，赛季来自真实赛事/赛季选项；切换只复用现有 overview 契约，不增加后端接口。
- 头像可以复用，但正常态不得出现首字母、空白或破图；返回后保留球队总览位置。

完成门槛：数据、选择层和榜单全部三张原型均能从球队页真实操作进入，选择状态与展示内容一致。

## 4. R1-M3：其余三页复核与证据收口

- 对帖子、球员、赛程逐页与原型复核，只修影响视觉验收的差异：版式、模块密度、间距、媒体裁切、分组标题和卡片尺寸；不得借机重构数据层。
- 帖子保持真实双列内容和分页；球员保持按真实位置分组的双列金色图片卡；赛程保持日期分组、真实队徽/比分/状态和比赛详情入口。
- 原型收藏星没有比赛收藏契约，不增加假按钮；可保留非交互视觉或省略。
- 360dp 与 140% 字体必须逐页检查，五个标签保持单行可操作，关键内容无 overflow、遮挡或裁切。
