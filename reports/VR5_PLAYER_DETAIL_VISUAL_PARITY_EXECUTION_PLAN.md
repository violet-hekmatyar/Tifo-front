必须按 M0 → M6 顺序闭环；每个模块完成生产实现和直接测试后再进入下一模块。

### VR5-M0：基线、数据和原型测量

1. 运行现有 5 个 F14 测试文件，记录基线实际数量；当前参考基线为 14 项通过。
2. 对固定球员复核上述 6 个 API，记录记录数、媒体 URL 和 `code=0`；不得因为原型示例不同而替换目标球员。
3. 测量 6 张原型的头部、Tab、页面边距、卡片圆角、列间距、主要字号和模块顺序，形成实现使用的简短视觉规格。
4. 保存当前 APK 球员详情截图作为 before 证据；不得把 P3 旧截图当作 VR5 最终证据。

完成门槛：固定数据可用、基线测试通过、原型状态映射无歧义。

### VR5-M1：沉浸式头部与五 Tab

- 移除当前独立绿色 AppBar 和带图标的大 Tab，改为与原型一致的酒红沉浸式头部：状态栏背景、返回、描边关注按钮、圆形头像、姓名、位置/年龄、当前俱乐部胶囊。
- 五个文本 Tab 固定为“总览、帖子、数据、比赛、生涯”，与头部连成同一酒红区域；选中态使用白色短下划线，未选中态降低透明度。
- 使用真实头像、年龄、位置和俱乐部；缺图、长名称、unknown 位置、退役和空俱乐部安全降级。
- 关注继续使用现有 `toggleEntity('PLAYER', id)`，保留 busy 防重复、成功权威结果、失败保持旧状态和提示。
- 360dp 与 140% 字体时 Tab 保持单行横向滚动，必须能实际滑动并点击“生涯”；返回优先 `pop`。

完成门槛：五个 Tab 共用同一头部且切换不重复请求；头部比例、颜色、留白和对齐接近原型。

### VR5-M2：总览长页

按原型顺序完成：

1. 俱乐部/国家队并排入口：俱乐部显示真实队徽和名称并可进入球队；国家队为 null 时保留同尺寸紧凑空态，不伪造国家队。
2. 个人资料：使用三列紧凑网格显示身高、年龄、号码、国籍、惯用脚和体重；可空值统一使用 `—`，不显示重复的“现役”等非原型大卡。
3. 效力经历：使用 `/teams` 真实记录形成原型“转会记录”位置的效力时间线；标题必须诚实使用“效力经历”，不伪造转会费、来源球队或不存在的转会动作。
4. 能力值：契约缺失时使用紧凑“暂无能力值数据”状态；不得根据赛季统计生成六维雷达或综合分。
5. 球员荣誉：契约缺失时使用紧凑“暂无球员荣誉数据”状态；不得拿球队荣誉冒充球员荣誉。

总览须可完整滚动，顶部与下半段分别取证。空能力/荣誉不得占用原型完整图表高度，也不能形成大面积空白。

### VR5-M3：帖子与比赛

帖子：

- 412dp 常规字体使用自然高度双列，封面比例、列间距、圆角、标题行数和信息密度对齐原型；360dp 或 140% 字体可安全降级单列。
- 展示真实封面、标题、摘要、类型、发布时间、点赞和评论；接口没有作者字段，不得伪造作者或认证标记。
- 无封面时收起图片区；有效内容 ID 进入详情，无效 ID 不跳转。

比赛：

- 按 `球员详情-帖子(1).png` 的实际比赛画面对齐日期分组、赛事、队徽、比分/时间、状态和圆角卡片密度。
- 保留真实比赛排序和状态；接口没有收藏操作时不放置可点击假星标。
- 有效比赛进入比赛详情；分页、刷新、错误重试和到底状态继续使用现有真实 controller。

两页首个内容必须紧贴 Tab 下方，不得出现自动 SafeArea 顶部空白。

### VR5-M4：数据页

- 使用 `/stats` 返回的真实记录建立“赛事＋赛季”选择；有多条候选时提供可操作选择层，只有一条时显示非交互标签，禁止死下拉按钮。
- 顶部摘要以两行三列展示进球、助攻、比赛、首发、分钟及可用的代表指标。
- 按原型实现绿色“总计/场均”分段。仅在 `appearances > 0` 时由真实总计除以出场数计算场均；无有效分母时禁用场均并保持诚实状态。
- 统计分组使用灰色标题带和紧凑行：进攻、组织、纪律、门将等，只显示现有字段。进度条仅用于有明确分子/分母的射正率等关系。
- 切换记录或总计/场均不得触发旧响应覆盖、重复请求或数据串页；0、null、负值、NaN、Infinity 安全。

完成门槛：标准尺寸首屏达到原型信息密度，至少完整展示摘要并进入第一个统计分组。

### VR5-M5：生涯球队/赛季两态

- 将默认描边 `SegmentedButton` 改为原型绿色实心“球队/赛季”分段控件。
- 球队态使用 `byTeam`，并以 `/teams` 匹配真实队徽、球队名、效力时间；表头和行显示出场、进球、助攻。
- 赛季态使用 `bySeason`，显示真实赛季名及出场、进球、助攻；不得把三个同名赛季错误去重。
- 职业与国家队区域维持原型表格层级；没有国家队生涯时显示紧凑空行/空态，不复制俱乐部数据。
- career 与 teams 继续独立 loading/error/empty/retry，一个失败不能遮蔽另一个；切换只使用已加载数据，不增加请求。

完成门槛：球队态和赛季态均能形成独立正式截图，结构、列对齐和密度与两张生涯原型一致。
