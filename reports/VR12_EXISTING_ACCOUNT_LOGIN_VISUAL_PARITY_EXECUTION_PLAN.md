## 模块与执行顺序

每个模块完成并通过其定向检查后再进入下一个模块，不顺带处理其他页面。

### M0：基线与量测

- 保存当前登录页和协议弹层截图，不作为最终证据。
- 从两张原型记录：绿色区/白色面板分界、品牌图标、标题、面板圆角、左右边距、协议行、弹层宽高、居中位置和按钮分栏。
- 在执行记录中写出原型像素、换算 dp、实现目标和允许误差；不得凭主观描述代替量测。
- 先跑现有 auth 与路由定向测试，记录基线，不改失败测试来迁就实现。

### M1：登录页整体骨架

- 页面上半部改为接近原型的整块绿色品牌背景，可用现有颜色、渐变和轻量代码矩形形成低对比足球纹理；禁止使用原型截图作背景。
- 白色操作面板从页面约中部开始并铺满宽度，只保留顶部大圆角，不再使用悬浮小卡片结构。
- 品牌标识使用现有足球图标置于白色圆角方块内；欢迎标题、英文副标题均水平居中。
- 标准宽度下白色面板顶部目标为屏幕高度的约 `48%～54%`；顶部圆角目标 `24dp±4dp`；品牌图标目标 `60dp±4dp`。
- 登录页使用局部系统栏样式：绿色背景上为浅色状态栏图标，退出页面后不得污染其他页面。

### M2：真实账号操作面板

- 保留用户名、密码、密码显隐、字段校验、错误提示、busy 防重、键盘 next/done 和真实注册入口。
- 表单使用原型的简洁纵向层级：紧凑输入区、绿色主按钮、轻量注册入口、底部协议行；不得增加原型不存在的大标题卡或装饰图标堆叠。
- 未勾选/已勾选协议状态清晰；协议文案保持“阅读并同意《用户协议》和《隐私政策》”。没有真实协议路由时只显示文字，不伪装链接。
- 键盘弹出时当前输入、错误、协议和登录按钮可滚动到达；关闭键盘后输入不得丢失。
- 登录成功继续由 `AuthController` 与既有重定向决定去首页或首次引导，页面不得重复导航。

### M3：协议确认弹层

- 将当前底部 Sheet 改为原型式屏幕中央白色圆角对话框，背景带半透明深色遮罩。
- 弹层包含：标题“服务协议及隐私保护”、真实说明文字、底部等宽“不同意 / 同意”两栏及分隔线；右侧同意文字使用品牌绿。
- 标准宽度下弹层宽度目标为屏幕宽度的 `70%～76%`，水平/垂直中心偏差不超过 `8dp`，圆角目标 `8dp～12dp`。
- 未同意时点击登录：字段合法才显示弹层且零请求；不同意、返回键或外部关闭均零请求；同意后勾选协议并只继续一次原登录请求。
- 重复点击、弹层重复打开、页面 dispose 和登录 busy 不得造成重复请求或异常。
- 注册页继续复用相同协议交互时，只允许获得同等弹层和行为修复，不做注册页视觉改版。

### M4：定向测试

新增 `vr12_login_visual_test.dart`，至少覆盖：

- 登录页不存在手机号验证码、一键登录、微信登录、游客和找回密码入口。
- 绿色区、白面板、品牌图标、标题、输入区、主按钮和协议行的真实 Rect/相对位置。
- 白面板分界比例、24dp 圆角、60dp 图标及居中关系在允许误差内。
- 协议弹层为居中 Dialog 而非底部 Sheet；宽度比例、中心偏差、等宽按钮和分隔结构达标。
- 不同意/返回/外部关闭零请求；同意后仅一次请求；已勾选后正常提交；busy 防重。
- 360dp、标准宽度和 140% 字体无 overflow、遮挡或不可点击；键盘态主操作可到达。
- 业务错误、网络错误和锁定错误保留输入并显示真实反馈。

几何验证必须使用 `tester.getRect`、尺寸或请求次数断言；仅查找 Widget 或 `takeException == null` 不足以证明视觉与交互通过。
