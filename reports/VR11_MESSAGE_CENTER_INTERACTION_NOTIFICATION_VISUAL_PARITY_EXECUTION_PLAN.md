## 2. 基线事实与实现原则

现有后端契约已经覆盖本阶段所需能力：

- `GET /api/app/notifications?pageNum&pageSize`
- `GET /api/app/notifications/unread-count`
- `POST /api/app/notifications/{notificationId}/read`
- `POST /api/app/notifications/read-all`

现有通知类型、目标预览、演员头像、内容封面、分页、单条已读和全部已读均可复用。本阶段不得为了视觉调整新增或改名接口、字段、枚举、分页包装或错误码。

当前 `/app/messages` 直接展示通知列表，缺少原型中的“消息首页 → 互动消息”两层结构。正确收口方式是：

1. `/app/messages` 改为消息首页，继续处于主底部导航壳内；
2. 新增 `/messages/interactions`，作为无底部导航的互动消息全屏页；
3. `/messages` 保持兼容并进入互动消息页；
4. `/settings/notifications` 继续复用真实互动通知页，不创造第二套通知逻辑；
5. `auth_redirect.dart` 对整个 `/messages` 路径族保持登录保护。

## 3. 范围边界

### 3.1 本阶段纳入

- 消息首页的标题、顶部动作、互动消息入口、摘要、时间、未读提示和底部导航；

### 3.2 明确排除

不得用硬编码联系人、虚构会话、假成功、静态通知数组或生产代码 fixture 填满 `消息.png`。原型里的会话行属于已排除私信能力；本阶段只保留真实“互动消息”入口，其余区域自然留白。

### 5.2 最小通知集

- 每条内容目标都能返回真实标题和 PNG 封面；
- 至少 3 条未读、至少 3 条已读，用于角标和状态验证；
- 时间使用固定值并保持倒序，不能依赖执行时刻随机生成；

### 5.3 数据安全

- 先检查并记录专用 ID 区间和 `dedup_key` 前缀未被占用；建议前缀 `VR11:M1:`，最终区间写入 Manifest；

- Validator 至少检查数量、收件人、演员、类型、目标可用性、封面、读状态、排序、重复键和非 DEMO 泄漏；

## 6. 视觉与交互目标

### 6.1 消息首页

- 白色主体、浅色系统栏和深色系统图标；标题“消息”居中；
- 标准设备下标题、顶部动作、首行起点、左右边距和纵向节奏按 `消息.png` 比例量测，不凭印象套通用 AppBar；
- 第一行是绿色圆形“互动消息”入口，右侧显示最近时间，副标题来自真实最新通知；
- 未读数量来自现有 unread-count；底栏消息角标与页面状态一致；
- 没有通知时仍保留可进入的“互动消息”入口，副标题显示“暂无互动消息”，不得整页替换成通用大空态；
- 原型右上角搜索/会话动作可以保留视觉入口，但点击必须明确提示“私信相关功能暂未开放”，不得进入假页面、假列表或假成功；
- 私信会话行不复刻、不伪造，其余空间保持干净留白；
- 沿用 VR1 已通过的底部导航，不修改其尺寸、阴影、选中态或其他 Tab。

### 6.2 互动消息页

- 白色全屏页面、左侧返回、居中标题“互动消息”，不显示底部导航；
- 行布局按原型：左侧约 40～44dp 头像，中部昵称与“动作 + 时间”，右侧约 40～44dp 方形圆角封面；
- 不使用通用大卡、绿色 AppBar、阴影、列表 chevron 或多层说明文字；
- 文案优先从现有 `title/content` 推导简洁动作句，不能硬编码演员名或内容 ID；
- 封面缺失或加载失败时使用统一紧凑占位，不能改变行高；
- 单条点击先执行既有已读请求，成功后进入真实目标；失败时保留未读状态并提示；busy 时防重复；
- 全部已读能力不得删除。可采用不破坏居中标题的紧凑顶栏动作，并覆盖成功、失败和 busy；正式原型对照图应使用稳定状态，不用弹出提示遮挡主体；
- 目标不可用时不跳转，使用紧凑、非破坏布局的提示；未知类型安全降级；
- 分页、下拉刷新和加载更多保持现有 controller 语义。

### 6.3 响应式

- 必测标准设备、实际 360dp 宽和 140% 字体；
- 昵称、动作、时间和标题可截断但不能互相挤压、溢出或遮住封面；
- 顶部动作和返回按钮保持至少 44dp 可点击区域；
- 页面底部内容不能被主导航或系统手势条遮挡。
