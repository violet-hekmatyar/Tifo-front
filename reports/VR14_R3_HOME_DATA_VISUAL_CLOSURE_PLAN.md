## 2. M0：同尺寸原型量测与失败基线

1. 完整读取 `首页.png` 和数据关注态目标图，记录原图尺寸及坐标换算依据。不能仅凭文件名判断选中状态。
2. 以 375dp 为主视觉比较宽度；设备 `984px / 420dpi` 实际为 374.86dp，按 375dp 处理，不能误判成窄屏。
3. 从原型量测：首页导航高度、列宽/列间距、比赛卡体/比分、评分卡模块、转会卡、讨论卡；数据页导航、球队文字筛选、首个日期位置。记录来源坐标、dp 数值和允许误差。
4. 首屏对照使用相同逻辑高度；长图后半段用滚动截图补齐并记录偏移。可提交连续长图，但必须保留原始截图，不能用大段白色补齐当作完整几何对照。
5. 为比赛时间完整显示、专用卡结构及数据球队筛选高度补失败测试。保留 R2 真实 API fixture 的类型、分页和首卡比赛断言。

验收规则：固定内边距、间距、控件尺寸与量测值原则上误差≤2dp；文字内容不同导致的整体高度变化单列解释。不得伪造原型比分、人物或数据来通过测试。

## 3. M1：首页完整视觉模块

### 比赛、内容和导航

- 比赛卡按原型恢复深青绿色卡体、突出比分、两侧队徽/名称与轻量状态；分别处理进行中、已结束、未开始。
- 修复含换行的时间字符串被单行截断：比赛时间可完整显示，日期/时分分别布局；如原型未显示日期，不占用比分中心位置。
- 内容卡按原型恢复图片比例、标题/作者/互动与热评条层级，避免用粗大字体和多余灰绿正文块取代原型结构。
- 顶部球队入口保留可辨认名称；采用真实显示名/短名与横向滚动，不以 30dp 标签或隐藏全部名称来满足边界断言。

### 评分、排名、讨论和转会

- 评分卡恢复原型的球员头像、名称、出场信息、星形/数字评分及比赛信息层级；字段不足时用明确空缺处理，不能虚构。
- 排名卡恢复简洁白底、标题、列标签与真实条目；不为凑模块高度填入假球队或积分。
- 讨论卡恢复蓝色话题块＋白色热门评论块；使用真实讨论内容与评论。
- 实现紧凑“转会快讯”展示卡。复用已有内容/关联和显式展示子类型，点击进入真实内容详情；不按标题关键词猜测。若需标记一个 DEMO 内容，只新增 R3 专用 Seed/Validator/Rollback/Manifest，精确到固定记录、来源和字段，验证幂等与条件回滚。未实现时必须报告未完成。

### 双列排列

- 当前 `index.isEven` 分列使比赛、排名、评分、热评全部落在左列。改进呈现策略，使同一真实前十条得到与原型接近的两列节奏：左上比赛、右上图文，其后内容与专用卡交错分布。
- 可以调整布局的列归属和按实际高度安排位置；保留所有卡、cardKey 和真实业务目标，不在客户端改变服务器 position 或曝光归因，不硬编码实体 ID。
- 保持后续分页追加稳定，不重排已显示卡或产生重复。
- 原型长图中的后续模块可滚动查看，不要求全部塞进短设备的第一个物理视口。

完成门槛：首页各类卡体和模块层级完成；转会卡实际出现；卡片分列不再形成一列全是辅助卡；标准375dp按量测通过，推荐/资讯/关注/球队筛选及点击可用。
