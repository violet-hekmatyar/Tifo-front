## 4. 视觉验收口径

后续任何页面不得仅凭测试通过标记为视觉完成。每张纳入原型至少需要：

1. 使用当前源码构建的 APK；
2. 使用与原型语义一致的真实 API 数据和页面状态；
3. 固定 Pixel 8 主尺寸、100% 字体截图，补充 360dp 和 140% 字体健壮性截图；
4. 原型与实机截图并排或半透明叠加对照；
5. 核对结构、模块顺序、几何尺寸、间距、颜色、字号/字重、圆角、阴影、图标、图片裁切和信息密度；
6. 应用内容区域不得以“风格接近”“功能存在”“无 overflow”代替一比一结论；
7. 页面正常态必须使用可访问图片，图片失败占位只验收为异常降级；
8. 不得为截图在 Widget 中硬编码球队、球员、比分或内容，继续以现有 API 契约为准。

建议对关键几何项采用 `±4dp` 以内的偏差门槛；模块缺失、顺序错误、整块配色错误、正常数据展示为空、图片由首字母替代等情况直接判失败。
