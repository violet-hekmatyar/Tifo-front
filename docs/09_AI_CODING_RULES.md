# 南看台前端 AI Coding 规则

> 版本：v0.1  
> 当前阶段：F00  
> 文档定位：约束 Codex/Cursor 在前端仓库中的行为。  
> 不负责：产品拍板、接口变更或替代人工验收。

## 分工与流程

人确认产品边界、架构、接口和验收；AI 只在明确范围内实现。每轮先阅读文档与本轮 Context Pack，只完成一个可验证功能闭环，运行对应检查；测试失败不得宣称完成。

## 固定边界

- 不更换技术栈：Flutter 使用 Riverpod，后台使用 Vue 3 + TypeScript；
- 不新增用户 H5、React、Bloc、微前端、Nuxt 或 SSR；
- 不根据截图猜接口字段，不复制后端内部数据库/Java 实现；
- 不修改 `D:\Football-APP`；
- 不硬编码 Base URL、Token、密码或密钥；
- 不扩大 P0，不批量生成无用抽象层；简单模块允许简化分层；
- 不自动执行 `git add`、`git commit` 或 `git push`；
- 每轮必须运行匹配的检查并报告文件、逻辑、结果、未完成项和风险。

## 前端 Context Pack

每轮应给出目标、阶段、相关主线文档、后端契约快照版本、允许/禁止修改路径、实现要求、验证命令和输出格式。接口任务必须优先阅读 05/07，页面任务优先阅读 02/04/06，基础设施任务优先阅读 03/04/08/10。

## 稳定 Prompt 模板

```text
当前目标：一个可验收闭环。
当前阶段：Fxx。
相关文档：列出前端权威文档和后端契约。
允许修改：精确目录或文件。
禁止修改：后端仓库、技术栈、范围外模块、敏感配置。
实现要求：模型、状态、路由、错误和安全规则。
验收方式：必须执行的格式化、静态检查、测试、构建或 smoke。
输出要求：修改文件、实现说明、测试结果、未完成项、风险、Git 建议。
```

禁止使用“把整个前端写完”“看着改”等开放式 Prompt。所有改动完成后先 Review diff，再由人工决定是否提交。
