## 3. R1-M1：通知数据关系修正

不新增表、用户、内容或评论。采用最小方案：

1. 将 8 条 VR11 演示通知统一为合理的 `CONTENT_LIKED`；
2. 使用演员与内容的不同组合，避免同一演员对同一内容产生重复点赞通知；
3. `secondary_target_type`、`secondary_target_id` 均设为 `NULL`；
4. 文案统一为自然的“某用户点赞了你的内容”；
5. 最新一条时间可用于消息首页显示“昨天”，其余通知使用合理倒序；互动列表时间不得出现带空格的“2 天前”；
6. Validator 新增以下检查：通知类型、二级目标必须为空、演员+目标组合不重复、目标内容作者为 10002；
7. 更新 Manifest。

由于原 Seed 不覆盖已有行，必须按 `Rollback → 新 Seed → Validator → Seed → Validator` 执行。第二次 Seed 行数仍为 8，非 VR11 通知不得变化。

## 4. R1-M2：像素返修

### 4.1 共用标题栏

- 标题从 22sp 收紧到约 18sp，并与原型字重接近；
- 保持标题真实居中，返回和右侧动作不能推移标题；
- 搜索、会话管理和返回按钮保留至少 44dp 点击区域，图标视觉尺寸按原型量测；
- 全部已读按钮只在确有未读时显示；未读为 0 时不占位。

### 4.2 消息首页

- 绿色互动入口从 56dp 收紧到约 44dp，内部白色图标同步缩小；
- 主标题约 16sp，副标题约 13～14sp，时间约 12sp；
- 收紧列表顶部空白和入口内部间距，使入口首行接近原型纵向起点；
- 继续只显示真实“互动消息”一行，不添加私信会话；
- 继续保留搜索/会话动作的“暂未开放”真实反馈；
- 不修改已通过的主底部导航组件。

### 4.3 互动消息列表

- 行高从 76dp 收紧到约 60dp；
- 头像与封面从 44dp 收紧到约 40dp；
- 昵称约 14sp，动作和时间约 12sp；
- 保持左侧约 16dp、右侧约 15～16dp，封面右对齐；
- 收紧标题下方到首行的空白，使第一行与原型接近；
- 无更多分页且无错误时返回空组件，不显示“没有更多消息了”；加载更多和失败重试仍保留；
- 单条已读、全部已读、失败回滚、busy、防重复、刷新、分页、目标跳转与返回链不得回归。

### 4.4 日期格式

- 1 天前显示“昨天”；
- 2～6 天显示“2天前”等无空格格式；
- 其他日期沿用简洁月日格式；
- 空时间继续安全降级。
