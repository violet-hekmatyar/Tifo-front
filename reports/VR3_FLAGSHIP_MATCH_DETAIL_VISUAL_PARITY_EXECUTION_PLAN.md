## 2. 范围与顺序

严格按 VR3-M0～M6 执行；前一模块的真实数据和测试不通过，不进入后一模块。

### VR3-M0：契约与数据门禁

- 复核旗舰比赛详情、overview、lineups、stats、player-stats、ratings 五类现有接口；
- 确认两队各 11 首发、7 替补，事件、球队统计、28 条球员统计和评分可读；
- 修复 Flutter 对既有 `fieldX/fieldY` 的丢失解析，使阵容可使用真实坐标；
- 按 `VR3_MATCH_DETAIL_BACKEND_REQUIREMENTS.md` 先验证比赛关联内容和 PLAYER_RATING 评论能力，只对确认缺口做最小后端实现；
- 不改 P1 比分、球队、球员、阵容和统计数据。

### VR3-M1：共用比赛头部与 Tab

- 使用 P1 可访问球场/体育场图片作为沉浸式深色头图，叠加返回、赛事/轮次、日期、双方队徽、比分、球队名和状态；
- 头部及 Tab 在五个页面保持固定视觉骨架，Tab 顺序为“评分、总览、阵容、排名、统计”，不显示当前的大号图标；
- 选中态使用原型的文字强调与短下划线，常规宽度五项同屏；
- 返回保持原数据页上下文，球队和球员入口继续使用真实路由。

### VR3-M2：总览

- 按原型顺序呈现“最新资讯 → 关联内容/战报封面卡 → 简要统计 → 事件”；
- 最新资讯使用比赛关联内容真实分页结果，双列紧凑卡显示封面、标题、作者/时间和互动摘要；没有真实视频类型时，关联大图只进入内容详情，不显示虚假播放能力和时长；
- 简要统计使用真实球队统计生成左右对称横向比较条；
- 事件使用中轴时间线，区分主客方向、进球、换人、黄/红牌和上下半场节点，球员/球队可跳转；
- 刷新失败保留旧内容，空数据只影响对应区块。

### VR3-M3：阵容

- 用真实 `fieldX/fieldY`、阵型和首发数据绘制上下半场绿色球场，两队各 11 人；
- 球员节点显示头像、号码/姓名、评分，并在真实数据存在时显示换人和牌类标记；允许复用同一球员图片，不允许用队徽或字母作为正常证据；
- 球场下依次展示双方教练、替补席和伤停/禁赛区；后端没有伤停数据时保留明确空态，不编造球员；
- 提供事件图例，球员点击进入球员详情；360dp 和 140% 字体下球场坐标不漂移或溢出。

### VR3-M4：统计与排名边界

- 统计按真实类型映射到“进攻、组织、防守”等分组，每项使用主客数值和成对横向条；未知类型安全显示，不丢值；
- 球员统计保留球队/位置筛选、分页和真实头像，可放在球队统计之后；
- “排名”Tab 继续展示 Backend V1 的 CURRENT_STANDING，不把当前排名称为赛前排名；
- 同页增加淘汰树入口，进入既有“正在开发”占位并可返回；不得绘制假晋级线或用重复卡片冒充原型树。

### VR3-M5：评分三态

- 评分列表使用主客队分段筛选，球员卡展示真实头像、姓名、球队、官方/媒体评分、用户均分、人数和我的评分；
- 点击球员进入评分详情态，组合既有 player-stats 与 ratings 显示球员资料、单场关键统计、我的评分、分布条和真实评论/回复；
- 评分输入使用原型式底部层：球员信息、五颗可交互星（映射后端 1～10 分并明确显示数值）、可选评论文本和发布按钮；
- 发布时评分与评论分别调用现有/补齐后的真实接口，任一失败必须明确提示且不能把另一个成功结果回滚成假状态；支持覆盖与撤销评分；
- 未登录时走现有登录门禁，不实现手机号验证码、微信登录或私信。

### VR3-M6：整体验证与证据

- 回归 loading、empty、error、retry、刷新保留、快速切 Tab、滚动位置、返回及图片失败降级；
- 只运行比赛详情、评论契约和直接受影响的定向测试，以及 `flutter analyze`、两个仓库的 `git diff --check`；
- 构建并安装同一份当前源码 APK，记录完整 SHA-256。
