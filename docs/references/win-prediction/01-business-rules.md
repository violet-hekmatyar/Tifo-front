# 球队输赢预测（预测 Tab）业务规则

> **依据**：飞书 wiki《tifo比赛详情预测 Tab 功能需求初稿》（文档标注“11月4日修改”，作者/团队：广州六边网科技有限公司）。

> **说明**：本文是对原文的整理与结构化，不新增产品结论；带有“【待确认】”的内容属于原文未定义或原型与文档冲突，集中记录在 [03-open-questions.md](03-open-questions.md)。
> **原文全文**：[source/feishu-doc.txt](source/feishu-doc.txt)

## 1. 一句话定位

在比赛详情页原有 5 个栏目（评分 / 总览 / 阵容 / 排名 / 统计）之后新增第 6 个 Tab「预测」：

- **赛前**：用户给“主胜 / 平局 / 客胜”分配概率，汇总成“球迷共识”，可自愿用看台豆参加挑战。
- **开赛**：判断锁定，不可修改、追加。
- **赛后**：Tab 变为“赛后复盘”，展示实际比分、洞察分、看台豆变化和“你赢在哪里”。

> 原文：“比赛未开始时用‘预测’，开赛后锁定，比赛结束后变成‘赛后复盘’。不接现金充值、提现和用户间交易，看台豆只做站内娱乐挑战和数字成就。”

## 2. 产品硬边界（不可做）

| 不做 | 原因（原文） |
| --- | --- |
| 现金充值和提现 | 会形成真实资金损失和兑付问题 |
| 看台豆转赠、交易 | 一旦可流通，就可能被当作可变现资产 |
| 赔率、奖金池、抽水 | 会明显强化博彩性质 |
| 滚球挑战、连续加注 | 容易制造高频刺激和追损 |
| 现金、彩票或高价值实物奖励 | 容易与博彩或抽奖混淆 |
| 站外博彩、跟单和私域返利入口 | 与资讯产品的边界冲突 |

另外：

- 看台豆不是现金，也不是可以交易的数字资产。
- 判断本身免费，不充值、不扣金币、不能转卖。
- 分享的复盘卡不可变现，不出现收益、赔率或跟单文案。

## 3. 页面状态机

| 比赛状态 | 预测 Tab 显示 | 用户可做什么 |
| --- | --- | --- |
| 未开赛 | 球迷共识、我的预测、看台挑战、热门玩法 | 提交或修改概率，选择是否挑战 |
| 比赛进行中 | 已锁定、当前共识、赛中情绪 | 查看，不能再修改或追加 |
| 已结束 | 赛后复盘、洞察分、看台豆变化 | 查看战绩和分享复盘 |

实现要点：

- 三个状态的切换以**开赛时间**和**比赛结算状态**为准，不以前端本地时间单独判断。
- 进行中进入页面需要明确展示“已锁定”，隐藏/禁用一切提交、修改、追加挑战入口。
- 已结束不再展示可操作的投入按钮；原文明确“不再展示可操作的下注按钮”。
- 原型三屏的比赛头图都写成“已结束 1:0”，但内容分别是赛前页、判断面板、赛后页，属于**占位数据**，不能据此推断状态与头图一致。

## 4. 赛前预测页

### 4.1 信息结构

| 区块 | 内容 | 规则 |
| --- | --- | --- |
| 比赛头图 + 栏目 | 保留现有头图与 5 个栏目，在最后增加“预测” | 预测不塞进总览或统计里 |
| 球迷共识 | 主胜 / 平局 / 客胜三个百分比 + 参与人数 + 变化原因 | 不是赔率，也不是平台承诺的概率 |
| 我的预测 | 未参与显示“还未提交判断 + 去判断”；参与后显示自己的概率与锁定状态 | 免费写下概率，加入球迷共识 |
| 看台挑战 | 完成预测前只能看、不能选豆；显示档位与规则提示 | 避免用户一进来就被引导投入 |
| 热门玩法 / 更多预测 | 原型展示“两队都进球”“下一球：巴萨”两条 | 原文只称“热门玩法”，未定义具体玩法【待确认】 |
| 底部主按钮 | 固定“写下我的判断”，滚动后仍能找到 | 打开判断面板 |

原文补充：

> “共识卡展示主胜、平局、客胜，旁边带参与人数和变化原因，避免只给一个没有上下文的百分比。”

> “‘我的预测’未参与时显示去判断，参与后显示自己的概率和锁定状态。”

> “看台挑战在完成预测前只能看，不能选豆；避免用户一进来就被引导投入。”

### 4.2 判断面板（写下我的判断）

| 项 | 规则 |
| --- | --- |
| 三个结果 | 主胜 p₁、平局 p₂、客胜 p₃ |
| 概率 | 三项合计必须 = 100%；概率越高代表越有信心 |
| 输入方式 | 三个滑杆；也可先用快捷模板再微调 |
| 快捷模板 | 原型为“接近五五开 / 看好巴萨 / 看好皇马”【文案待确认】 |
| 免费提交 | 不参加挑战时只提交免费预测 |
| 修改 | 开赛前最多修改 **3 次**；开赛后锁定 |
| 挑战档位 | 不参与 / 10 豆 / 30 豆 / 50 豆 |
| 挑战方向 | 只能挑战自己概率最高的结果 |
| 挑战次数 | 每场挑战一次；确认挑战后本场判断一起锁定 |
| 禁止项 | 不追加、不滚球、不借豆 |
| 提交按钮 | 原型“提交判断并开始挑战”；不参与挑战时的按钮文案原文未给出【待确认】 |

原文：

> “点击底部按钮后弹出判断面板。用户给主胜、平局、客胜分配概率，三项合计 100%。也可以先用快捷模板，再自己微调。”

> “不参加看台挑战时，只提交免费预测；开赛前最多修改 3 次。”

> “参加挑战时，只挑战自己概率最高的结果；可选 10、30、50 看台豆。”

> “确认挑战后，本场判断一起锁定；不追加、不滚球、不借豆。”

> “比赛正常结算后，猜中返还本金并给奖励，猜错扣除挑战豆，比赛作废则返还。”

**关键推论**：参加挑战会在提交时立即锁定判断，因此“最多修改 3 次”只适用于**未参加挑战的免费预测**；挑战提交后不能再改。该推论需产品确认。

## 5. 球迷共识

- 系统把所有用户的概率汇总后动态显示，代表“球迷意见”，不是赔率，也不是平台承诺的概率。
- 共识会随新信息变化（原文示例：主胜概率从 52% 降到 46%），可能原因包括：
  - 主队首发阵容轮换；
  - 核心后卫受伤；
  - 客队近期状态提升；
  - 大量球迷改变了判断。
- 原文借用了 Polymarket“概率随新信息变化”的体验，但没有资金仓位，也没有买卖获利。

【待确认】聚合算法、是否包含自己、刷新频率、参与人数口径、展示“变化原因”的数据来源，原文均未定义。

## 6. 洞察分（0–100）

### 6.1 公式

用户对三个结果分配概率 `p₁, p₂, p₃`（合计 100%）。赛后实际结果记为 one-hot：

- 主胜：`y = (1, 0, 0)`
- 平局：`y = (0, 1, 0)`
- 客胜：`y = (0, 0, 1)`

先算 Brier Score：

```
B = (p₁ - y₁)² + (p₂ - y₂)² + (p₃ - y₃)²
```

再换算成 0–100 的洞察分：

```
S = round(100 × (1 - B / 2))
```

- `round` 为四舍五入。
- 页面显示整数分，**后台结算也必须使用同一个整数**，避免用户看到的分数和实际奖励不一致。
- 一场比赛显示 0–100 分；完成多场比赛后再展示长期校准能力与准确率。
- 看台豆输赢与洞察分**分开记录**，避免把运气当成判断力。

### 6.2 原文算例：判断 64 / 22 / 14

| 实际结果 | Brier Score | 洞察分 | 展示 |
| --- | --- | --- | --- |
| 主队（巴萨）胜 | `(0.64-1)² + (0.22-0)² + (0.14-0)² = 0.1976` | `100 × (1 - 0.1976/2) = 90.12` | **90** |
| 客队（曼城）胜 | `(0.64-0)² + (0.22-0)² + (0.14-1)² = 1.1976` | `100 × (1 - 1.1976/2) = 40.12` | **40** |

原文结论：

> “洞察分奖励的不是‘敢喊’，而是‘概率给得准’。高概率押错会掉分，合理分配概率则更容易拿到高分。”

> “评分不只奖励‘猜对方向’，还会检查用户是否过度自信。一个总说‘90% 必赢’却经常猜错的人，长期分数会下降；一个给出合理概率、长期判断稳定的人，会获得较高排名。”

## 7. 看台豆挑战与结算

### 7.1 参数

- 初始本金：每个账号 1,000 豆；注册时发放，存量账号登录或执行补发脚本时发放；钱包按 `user_id` 唯一，不重复发。
- 挑战豆 `C ∈ {10, 30, 50}`。
- 方向命中定义：**用户概率最高的结果 = 实际结果**。
- 基础收益系数：

```
R = min(0.8, max(0, (S - 60) / 50))
```

| 洞察分 S | 奖励率 R |
| --- | --- |
| 60 | 0% |
| 70 | 20% |
| 80 | 40% |
| 90 | 60% |
| 100 | 80%（上限） |

> `S ≤ 60` 时 `R = 0`：方向命中只返还本金，没有额外奖励；方向未命中仍然扣除 `C`。

### 7.2 结算规则

| 结果 | 处理 |
| --- | --- |
| 方向命中 | `奖励豆 = C × R`；用户最终拿回 `C + 奖励豆`（返还本金 + 奖励） |
| 方向未命中 | 不管洞察分多少：`亏损 = C`，扣除挑战豆，不返本金 |
| 比赛取消或无法结算 | `亏损 = 0`，原数返还挑战豆 |

原文还规定：

- 确认挑战后，本场判断一起锁定。
- 不追加、不滚球、不借豆。
- 每场挑战一次，开场锁定。
- 看台豆输赢和洞察分分开记录。

### 7.3 原文算例：余额 1000，挑战 50 豆

**方向命中、洞察分 90**（R = 0.6，奖励 = 50 × 0.6 = 30）：

```
提交挑战：1000 - 50 = 950
完成结算：950 + 50 + 30 = 1030
最终：看台豆 1030，本场净收益 +30
```

**方向未命中**：

```
提交挑战：1000 - 50 = 950
完成结算：不返还
最终：看台豆 950，本场净亏损 -50
```

**注意**：`C × R` 可能不是整数（例如 S=61、C=10 时为 0.2），奖励豆的取整方式原文未定义【待确认】。

## 8. 排行榜

原文只给出方向，没有原型与规则：

- **洞察榜**：看谁长期预测得准。
- **看台榜**：看谁在用豆挑战中表现好。
- **好友联赛**：优先展示熟人排名，提高参与和讨论意愿。

## 9. 内容与合规文案

- 页面固定说明：“娱乐性质竞猜，不涉及现金”。
- 原型写成“说明说明说明”，是占位符；正式实现需要替换为规则说明入口。
- 分享复盘卡不得出现收益、赔率、跟单文案。
- 不出现“充值 / 提现 / 兑换 / 交易 / 奖金池 / 抽水”等表述。

## 10. 原文待定项

| 规则 | 当前建议 | 讨论点 |
| --- | --- | --- |
| 初始额度 | 每个账号发放 1,000 豆（注册即发；存量用户已补发） | 已定；是否按赛季重置仍待定 |
| 获取方式 | 观赛任务、发布分析、完成复盘、好友联赛 | 需要限制每日上限 |
| 挑战档位 | 10、30、50 豆 | 是否需要高信心档 |
| 成功奖励 | 按赛前共识难度分为低、中、高三档 | 奖励数值后台可调 |
| 不可做 | 充值、提现、转赠、交易、兑换现金或实物 | 建议作为产品硬边界 |
| 重置 | 赛季结束清零，保留徽章和历史战绩 | 避免长期囤积 |

**冲突提示**：上表写“成功奖励按赛前共识难度分三档”，而 5.3 的结算公式只按洞察分 `S` 计算，两者口径不一致【待确认】。
