# VR14-R2 首页组合策略与根页面证据最终计划

## 1. 本轮明确授权

允许对后端 `recommend` 首页的卡片组合阶段做一次**类型感知、非破坏性的有限调整**，目的是让现有真实候选中的比赛、排名、球员评分和讨论进入第一页。该授权仅覆盖首页组合策略，不等同于重写推荐系统。

允许修改：

- `HomeFeedCompositionService`、直接配置类及其定向测试；
- `FeedService` 中仅与 recommend 组合/分页顺序直接相关的调用；
- 首页 Feed DTO/可选展示子类型和直接 Widget；
- 数据根页顶部控制区；
- 本人页关注球员头像媒体链路；
- 必要的固定 DEMO 内容展示子类型数据及其独立 Seed/Validator/Rollback。

禁止：

- 修改客户端 `pageSize=10`；
- 修改 API 路径、分页字段语义、推荐候选查询上限或其他 Tab 的排序；
- 在生产代码硬编码比赛、球队、球员、内容 ID；
- 用 fixture、截图拼接或客户端假卡替代真实 API；
- 重做消息、详情、发布、搜索、设置、登录等已完成模块；
- 实现私信、IM、WebSocket、Push、手机号/微信登录或完整淘汰树。

## 3. M1：recommend 首页前缀类型组合策略

### 行为要求

只在 `tab=recommend` 且候选真实存在时，对组合后的第一页前缀做稳定、类型感知排列：

1. position 0 为优先级最高的 `MATCH`；
2. 前 10 条至少包含：
   - `MATCH` 1 张；
   - `RANKING` 1 张；
   - `PLAYER_RATING` 1 张；
   - `DISCUSSION` 或 `HOT_COMMENT` 1 张；
   - `CONTENT` 至少 3 张；
3. 同类卡内部保持推荐结果原有相对顺序；候选不足时自然降级，不生成假卡；
4. 所有 `cardKey` 唯一，`position` 连续，`impressionId`、算法版本和推荐归因完整；
5. page 1/page 2 之间不得重复或漏卡，`total/pages/pageSize` 语义不变；
6. `news`、`following`、`match`、球队筛选及非首页调用保持原顺序；
7. 不修改 `max-ratio=0.20` 和 `min-gap=3` 的全局默认值。类型多样性只约束 recommend 的第一页前缀，不提高整条 Feed 的辅助卡总比例。

### 实现约束

- 按卡片类型和现有推荐分数工作，禁止使用实体 ID、标题关键词或 DEMO 专属分支；
- 优先在组合服务完成，避免客户端重新排序导致推荐曝光归因错误；
- 分页前形成唯一稳定序列，再统一切页。

### 必测场景

- 候选齐全；缺比赛；缺排名；缺评分；只有少量 core；重复 cardKey；第二页；非 recommend Tab；匿名与登录态。

## 4. M2：首页专用卡与首屏视觉

### 工作

1. 用修复后的真实 API 前 10 条驱动首页，不使用另一份手工卡表。
2. 按 `首页.png` 的顺序重心收口双列瀑布：左上比赛卡、右侧图文内容，首屏内出现比赛、评分、排名和讨论专用卡。
3. 补齐原型中的紧凑“转会快讯”表达：
   - 优先复用 `content.card_type` 或现有 payload；
   - 若现有 Feed 未透出该信息，可增加一个向后兼容的可选展示子类型字段；不得改变既有必填字段；
   - 只对明确标记的内容使用紧凑转会卡，点击仍进入真实内容详情；禁止按标题关键字猜测。
4. 首页球队快捷区在标准宽度至少完整呈现三个球队入口与菜单；360dp 可横向滚动，但不得把入口挤成不可辨认的半个图标。
5. 首屏图片避免连续复用同一球场图；允许复用已有图片，但相邻主要卡至少使用两类不同封面。
6. 保留推荐、资讯、关注、球队筛选、发布、搜索与全部卡片跳转。

### 数据要求

如必须标记一条固定 DEMO 转会内容，新建 VR14-R2 专用 Seed/Validator/Rollback/Manifest：只修改固定 DEMO ID 的展示子类型，Seed×2 幂等，Rollback 仅在字段仍等于 R2 写入值时恢复。不得再次批量改 144 条热度。

### 完成门槛

- 真实 API 前 10 条和实机首屏都满足 M1 类型门槛；
- 首页 position 0 的比赛卡位于左上；
- 排名、评分、讨论和紧凑转会/动态卡无需下拉到第二页即可看到；
- 标准、360dp、140% 字体无裁切、重叠或底栏遮挡。

## 7. 最终通过条件

VR14 仅在以下条件全部满足后才能提交关闭复验：

- 真实 recommend 前 10 条包含比赛、排名、评分、讨论/热评和至少三条内容，且首卡为比赛；
- 前后端测试使用同一真实响应，不再用超出 pageSize 的理想假列表；
- 首页首屏专用卡和双列重心与原型一致；
- 数据对照左右均为原型实际“关注”状态，顶部赛事入口结构一致；
- 本人页关注球员显示图片，不是首字母降级；
- pageSize、全局 min-gap、API 分页语义和非 recommend Tab 均未回归；
- SQL 只读验证、定向测试、分析、差异检查和同 APK 证据全部通过。
