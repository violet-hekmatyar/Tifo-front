# P3 足球重点页面与淘汰树入口执行计划

日期：2026-09-18

## 1. 阶段目标

在 P1 数据和 P2 首页通过的基础上，完成数据中心、比赛详情、球队详情、球员详情的真实 API 页面验收，并补齐杯赛页面可发现的“淘汰树/总览”入口与诚实占位页。

页面结构、字段和状态以现有 Backend V1 API 与 Flutter model/repository 为准；不为了还原原型猜测接口字段，不伪造完整淘汰树数据。

## 2. 执行顺序

严格按以下模块执行，一个模块通过后才能进入下一个：

1. P3-M0：基线、契约和新鲜 APK 门禁；
2. P3-M1：数据中心真实数据与视觉验收；
3. P3-M2：比赛详情总览、事件、阵容/排名/统计/评分状态；
4. P3-M3：球队详情总览、动态、球员、数据和赛程；
5. P3-M4：球员详情总览、动态、数据、比赛和生涯；
6. P3-M5：杯赛淘汰树入口、正在开发占位及 P3 阶段验收。

## 3. 统一边界

- 不修改 Spring Boot、数据库、SQL、seed、API 路径、请求参数或响应契约；
- 复用 P1 已验收球队、球员、比赛、媒体和内容数据；
- 不处理历史比赛 `50004`，不修改 Feed 排序或 P2 首页已通过代码；
- 不实现完整淘汰树后端模型，不根据比赛列表推导伪造对阵关系；
- 不新增依赖，不运行无关全量测试，不提前进入 P4 页面；
- 生产 Widget 不硬编码截图中的球队、球员、比分、排名或赛事；
- 图片、空列表、错误、长文案和大字体必须安全降级，路由返回和分页状态不得回归。

## 4. 模块验收要求

### P3-M0：基线、契约和 APK 门禁

- 核对数据中心、比赛、球队、球员路由以及现有 API/repository 调用链；
- 运行当前 football 定向测试和 `flutter analyze` 作为基线；
- 对联赛、比赛列表/详情、球队详情/内容、球员详情做只读 API smoke；
- 使用当前源码构建并安装新 APK，记录设备、后端地址、时间和 SHA-256；
- M0 不修改业务代码，基线不通过不得进入 M1。

### P3-M1：数据中心

- 验收赛事、赛季、赛程、积分榜、球员榜和球队榜的真实字段、筛选、分页、刷新和返回保持；
- 覆盖 360dp、412dp、140% 字体、空态、缺图、长名称和快速筛选竞态；
- 保存数据中心主 Tab、筛选和真实数据截图。

### P3-M2：比赛详情

- 验收总览、资讯/战报、事件、阵容、排名、统计和评分现有契约状态；
- 有真实数据则完整展示，无接口能力则显示明确空态，不推导或伪造字段；
- 覆盖比分、状态、事件时间线、返回、Tab 保持、评分失败回滚和大字体截图。

### P3-M3：球队详情

- 验收球队头部、总览、动态、球员、数据和赛程真实响应；
- 复用真实队徽、球员头像、球队内容和比赛数据；
- 覆盖分页、刷新失败、关注状态、球员/比赛/内容跳转和返回状态截图。

### P3-M4：球员详情

- 验收头像、基础资料、当前球队、总览、动态、数据、比赛和生涯；
- 真实字段缺失时保留明确空态，不显示伪造能力雷达或统计；
- 覆盖现役/退役、租借/历史球队、分页、失败重试、球队跳转和大字体截图。

### P3-M5：淘汰树入口与阶段收口

- 在现有杯赛页面提供可发现的“淘汰树/总览”入口；
- 进入稳定路由后显示“淘汰树正在开发”占位，可正常返回，不展示伪造对阵；
- 汇总 M0-M4 测试、API smoke、APK 和 Android 截图，登记 P3 完成或最小补修项。
