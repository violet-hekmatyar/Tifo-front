## 2. 已确认契约与产品边界

1. 当前 `UserInfoVO` 和 Flutter `AuthUser` 不含手机号；数据库 `sys_user.phone` 可选存在。
2. 允许在原有用户响应中增加向后兼容的 `phoneMasked`：只能返回类似 `+86 185****9583` 的脱敏值；不得返回完整手机号、密码散列或其他敏感字段。
3. 若当前用户没有手机号，客户端显示“未绑定”；不得写死原型号码或从用户名猜测手机号。
4. 当前没有修改密码、换绑手机号、注销账号 API，本阶段不得新造接口。点击对应行只显示统一、可理解的“当前版本暂未开放”反馈，不改变用户或会话状态。
5. V1 没有服务端 logout API；真实退出登录继续调用既有 `AuthController.logout()` 清除本地 Token，并依赖既有路由重定向到 `/login`。
6. “通用设置”“通知设置”“语言设置”只复刻原型入口外观；若项目没有对应真实设置能力，点击显示非欺骗性提示，不创建空白页或假开关。

## 3. 原型视觉基线

原型为 750×1624，按 2 倍图换算为 375×812dp。M0 必须再次量测并记录实际像素，以下值作为首轮目标：

| 项目 | 目标 |
| --- | --- |
| 页面背景 | 近 `#F5F6F7` 的浅灰，系统栏与页面连贯 |
| 标题 | 顶部居中“设置”，约 19～20sp、半粗体 |
| 返回入口 | 左侧独立细线箭头，不使用带底色按钮 |
| 首个白色分组 | 左右约 10dp，顶部约 106dp，圆角约 12～14dp |
| 设置主页分组 | 4 行，每行约 50dp；图标约 24dp；分隔线左右内缩约 25dp |
| 账号安全分组 | 3 行，每行约 50dp；右侧值为浅灰，箭头靠右 |
| 退出登录 | 独立白色圆角块，左右约 24dp，顶部约 330dp，高约 54dp |
| 内容密度 | 首屏上半部完成主要内容，下半部保持大面积浅灰留白 |

Android 状态栏图标、字体栅格与 iOS 原型的系统差异可豁免；应用内容区的结构、行高、边距、圆角、字号、图标、分隔线和留白不得用平台差异解释。

## 4. 顺序执行模块

### M0：基线、量测与契约确认

1. 记录前后端 commit、工作树已有改动和当前 APK SHA-256，不覆盖用户改动。
2. 对两张原型建立量测表，至少记录页面背景、标题基线、返回箭头、分组外框、各行高度、图标尺寸、分隔线、退出按钮和右侧值/箭头位置。
3. 运行当前 `f19_settings_acceptance_test.dart`，记录基线；旧断言与本计划冲突时只按本计划更新，不得通过删除交互或错误处理来让测试变绿。
4. 核对以下权威契约：后端 `UserInfoVO`、`AuthService.toUserInfo`、Flutter `AuthUser.fromJson`、`AuthController.logout()` 和 `/settings` 路由。
5. 选用一个已有登录账号调用 `/api/auth/me`，只记录是否存在手机号及最终脱敏结果，不在报告中写完整手机号、Token 或密码。

完成门槛：量测表、当前差异、目标账号和敏感数据处理规则均写入执行记录后才能改代码。

### M1：手机号脱敏字段最小闭环

1. 在后端 `UserInfoVO` 增加可空 `phoneMasked`；不修改路径、包装结构、状态码或既有字段。
2. 在 `AuthService.toUserInfo` 中统一生成脱敏值，使注册、登录和 `/me` 返回一致。规则至少覆盖：
   - 空值返回 `null`；
   - 中国大陆 11 位号码展示为 `+86 前3位****后4位`；
   - 其他合法长度只保留最少必要首尾字符，中段使用 `*`；
   - 过短或异常数据不得原样泄露，安全回退为 `****` 或 `null`。
3. 增加后端定向测试，证明完整手机号和 `passwordHash` 不会出现在用户响应 JSON 中。
4. Flutter `AuthUser` 增加可空 `phoneMasked` 并兼容字段缺失；补充复制/构造路径，不能破坏登录、恢复会话和 onboarding。
5. 不新增数据库写入，不修改现有用户数据，不添加换绑、验证码、密码或注销接口。

完成门槛：带手机号和无手机号两类用户均能安全解析；API 只暴露脱敏值，旧客户端契约保持兼容。

### M2：设置主页视觉复刻

1. 以原型结构重做 `/settings`：浅灰背景、居中“设置”、独立返回箭头、白色四行分组和独立退出登录块。
2. 四行顺序与文案必须固定为：
   - 账号与安全；
   - 通用设置；
   - 通知设置；
   - 语言设置。
3. 使用与原型语义接近的线性图标：盾牌、齿轮、通知铃、语言；图标统一深色，不使用当前绿色强调和副标题。
4. 账号与安全进入现有 `/settings/account`；其余三项点击显示统一的轻量提示，说明当前版本尚未提供对应设置，不跳到编辑资料或互动消息页。
5. 退出登录从四行分组中移出，保持黑色居中文案和真实确认弹层；busy 防重复、取消零调用、失败留在设置页并显示错误、成功进入登录页。
6. 删除设置页对 `mySummaryProvider` 和编辑资料加载逻辑的无用依赖；编辑资料入口仍由 VR9 已验收的个人主页提供。

完成门槛：标准 375dp 结构、顺序、密度和留白与 `我的-设置.png` 对齐，所有入口都有真实导航或明确反馈。

### M3：账号与安全页视觉与安全行为

1. `/settings/account` 使用与原型相同的浅灰页面、居中标题“设置”和返回箭头；不要继续显示头像、用户名、角色、状态、用户 ID 大卡。
2. 白色圆角分组严格包含 3 行：手机号、修改密码、注销账号；每行约 50dp，分隔线、右侧箭头和文本位置按量测结果实现。
3. 手机号右侧显示 `AuthUser.phoneMasked`；为空时显示“未绑定”。完整手机号不得进入 Widget、日志、截图报告或测试 golden 描述。
4. 点击手机号显示“当前版本暂不支持换绑手机号”；点击修改密码和注销账号分别显示明确的未开放提示。三者不得调用网络、退出登录、删除数据或显示成功状态。
5. 提示可使用同一紧凑 SnackBar 或底部层，但不得永久占用原型主体空间；关闭后页面结构不变。
6. 用户为空时保留安全错误态和返回能力；不得用原型号码作为占位。

完成门槛：`我的-设置-账号与安全.png` 的三行结构通过视觉量测，手机号来源真实且脱敏，敏感操作没有伪实现。
