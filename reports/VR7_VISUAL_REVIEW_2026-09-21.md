## 2. 阻塞项

### P1-1：帖子图片填写态正式证据不成立

`02_post_filled.png` 与 `formal_02_post_filled_image.png` 中，已选图片区域只出现悬浮删除按钮，缩略图主体为空白；它们不能作为“图片正常显示”的正式验收图。过程图 `17_post_filled_image.png` 能显示缩略图，说明能力可能存在，但正式证据选取或等待时机错误，仍必须重采。

同时，当前图片格约占屏幕宽度 29%，原型约为 19%；实现把三等分 Grid 的单元格直接用作图片格，明显偏大。M0 将原型像素值近似当成逻辑 dp 使用，换算方法需要纠正。

### P1-2：新建文章初始态存在原型没有的大区块

`03_article_empty.png` 在正文下方显示“关联 0/10”，把原型的大面积留白切断。VR7 计划已要求新建态不能首屏堆叠关联管理表单，因此该状态直接不通过。既有文章编辑能力可以保留，但新建初始态只能用紧凑、真实可操作的次级入口承载足球关系。

### P1-3：热点事件页结构与原型明显不同

原型 `选择热点事件.png` 没有搜索框，列表紧接顶部标题；当前 `05_hot_event_picker.png` 增加大搜索框和大段空白，把首条事件下压到页面约四分之一处。

当前热点缩略图使用 `128dp`，实际约占屏幕宽度 31%，原型约为 17%；列表密度因此明显低于原型。此处应以原型宽度比例换算，不能把 750px 原型中的 128px 直接实现为 128dp。

### P1-4：编辑器底部工具结构未按计划收口

- 帖子页已经有“添加话题/关联热点事件”标签入口，下一行又重复显示 `# / 火焰` 两个入口；原型下一行是工具区，且 VR7 计划明确要求保留真实图片入口。
- 当前帖子底部没有独立图片工具按钮，只能点击正文中的大添加格。
- 文章页关联入口使用描边样式，底部工具与原型的层级、密度仍有差距。
- 140% 字体证据中“取消”换成两行，不能视为响应式通过。

### P1-5：逐图对照材料不满足人工验收要求

`comparison_01`～`comparison_05` 实际是原型文件副本，不是原型与实机截图的并排/叠加对照；`VISUAL_COMPARISON.md` 也只有文件映射，没有结构、比例、间距、字体和差异结论。

`08_published_detail_relations.png` 可见标题、正文和图片，但画面中没有 TOPIC/HOT_EVENT 标签，不能单独证明“详情关系可见”。API 回读可以证明持久化，但正式证据名称与画面内容不一致。

### P1-6：Rollback 引用保护遗漏 NULL remark

`VR7_M1_PUBLISH_SUBJECT_ROLLBACK.sql` 当前使用：

```sql
r.remark NOT LIKE 'VR7-M1-relation-%'
```

真实用户发布产生的 `content_relation.remark` 为 NULL；SQL 三值逻辑会使该条件不成立，Rollback 可能删除仍被用户内容引用的 VR7 目录行。必须改为：

```sql
r.remark IS NULL OR r.remark NOT LIKE 'VR7-M1-relation-%'
```

这只修复保护条件，不执行最终 Rollback，也不改现有数据。

## 3. 非阻塞差异

- 真实讨论数较原型的 299 小是正确行为，不得为视觉密度伪造数字。
- 热点图片可以复用 P1 PNG，不要求每行不同。
- 因现有契约缺失而省略表情按钮可接受；但已支持的图片和文章足球关系应使用真实入口呈现。
- 临时用户态转发不作为产品代码问题；本轮 API 已直接可读，不要求为端口环境返工。
