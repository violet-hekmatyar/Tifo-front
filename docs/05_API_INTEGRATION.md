## 基础接入

Base URL 必须按环境配置，不得硬编码服务器地址。接口前缀包括 `/api/auth/**`、`/api/app/**`、`/api/admin/**`、`/api/public/**`、`/api/file/**`。需要登录时发送：

```http
Authorization: Bearer <access_token>
```

统一响应由网络层一次解析为 `code / message / data / traceId`；分页数据统一为 `records / total / pageNum / pageSize / pages`。页面不得自行兼容多套返回格式，也不得根据截图或数据库字段重建契约。

## 错误处理

| code | 前端原则 |
|---:|---|
| `40001` | 展示可理解的参数错误，表单定位可修复字段 |
| `40101` / `40102` | 串行清理会话并跳转登录，避免重复弹窗和并发跳转 |
| `40301` | 展示无权限；后台 USER 会话按安全文档清理 |
| `40401` | 展示资源不存在并提供安全返回路径 |
| `40901` | 根据业务提示冲突，必要时刷新真实状态 |
| `50001` | 通用错误页/提示，并保留 `traceId` 供排查 |

网络断开、超时、取消、HTTP 非成功状态和业务 `code != 0` 必须区分。日志可记录路径、错误码和 traceId，不得记录完整 Token 或敏感请求体。

## URL 与模型

后端返回相对图片 URL 时，统一由 URL resolver 使用当前环境 Base URL 拼接；绝对 URL 需按允许策略直接使用。DTO/VO 在网络边界转换为前端模型，页面不接触后端 Entity 概念。未知枚举或 `cardType` 必须有兼容占位和可观测日志，不能导致整个列表崩溃。

## 页面与接口关系

页面只依赖按业务域封装的 API：认证/首次选择、feed、内容互动、足球数据、用户中心、管理用户内容、文件。具体路径和实际已实现范围以最新后端契约的 Current Implementation Notes 为准；计划接口不得当作已可用接口。

## 变更流程

后端先更新并确认原始契约 → 运行同步脚本 → 在 `references/BACKEND_API_CHANGELOG.md` 登记影响 → 更新前端 API 层与模型 → 完成单元/联调/smoke → 再修改页面。禁止只改页面临时适配后跳过统一网络层。
