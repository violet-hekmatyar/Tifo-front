## 3. 当前基线与必须关闭的差距

当前 `FootballDataPage` 使用大面积绿色 `AppBar`、“数据”标题、两行大号 `ChoiceChip`、榜单四宫格下拉表单和大尺寸通用比赛卡。P3 截图与原型的主要差距为：

1. 顶部缺少“重要 / 关注 / 联赛 / 欧冠 / 杯赛 / 菜单”的紧凑赛事导航；
2. 赛季与四类数据入口层级错误，控件高度和留白显著偏大；
3. 比赛卡的联赛、状态、队徽、比分/时间和战报条没有形成原型层级；
4. 正常态队徽仍可能降级为首字母；
5. 积分榜是通用列表，列宽、表头、行高和分区底色与原型不同；
6. 球队榜和球员榜缺少左侧固定指标栏，当前筛选表单占用大量首屏；
7. 同屏信息量明显低于原型，底部导航遮挡安全区的风险需重新验证。

以上差距全部关闭后才能提交 VR2 验收。

## 4. 实施要求

### VR2-1 数据中心外壳与赛事导航

- 移除页面主体中的大号绿色标题栏，改为白底、紧凑、安全区内的赛事导航；
- 第一行按原型建立“重要、关注、联赛/杯赛入口、固定菜单”，选中项使用深色文字和短绿色下划线；
- 联赛和杯赛入口使用 API 图片；不可解码时复用项目内中性足球/队徽图片，正常验收态不得显示首字母；
- 横向内容可滚动，但右侧菜单始终可见；360dp 和 140% 字体下不得溢出；
- 菜单内保留现有“淘汰树”入口，仍进入 `/football/knockout-tree` 占位页，不新增真实树数据；
- 重要/关注与具体联赛继续调用现有 `ImportantSource`、`FollowingSource`、`LeagueSource`，不改变接口语义。

### VR2-2 联赛上下文与状态同步

- 选中具体联赛后显示第二行紧凑控制：赛季入口以及“赛程、积分榜、球员榜、球队榜”；
- 赛季入口采用原型式单行按钮；多赛季/阶段可用紧凑底部选择层，不能继续把多个 `DropdownButtonFormField` 常驻首屏；
- 顶部联赛、赛程 Controller 与榜单 Controller 的联赛/赛季状态必须同步，切换页面不能跳回错误联赛；
- 重要/关注赛程可复用现有已关注球队接口显示紧凑球队筛选条；没有真实关注球队时自然收起，不伪造球队；
- 切换四个 section 保持可返回、可刷新和稳定状态，不重复请求或打乱后端顺序。

### VR2-3 赛程列表和比赛卡

- 内容区使用原型浅灰背景、紧凑日期标题和白色圆角比赛卡；
- 日期按现有排序和真实 `matchTime` 分组，今天/明天仅在日期确实匹配时显示，不伪造；
- 卡片顶部显示联赛/阶段信息与状态位；收藏星仅作为无业务状态的装饰图标时必须不可点击、不可宣称已持久化，不新增假收藏逻辑；
- 中部为两队图片、队名及居中比分/开赛时间；已结束突出比分，未开始突出时间，状态文案颜色与原型层级一致；
- 有真实战报时显示底部灰色战报条并保持原路由；无战报时不伪造文案；
- 412dp 下首屏至少呈现两个主要比赛卡区域；360dp/140% 下队名、日期、比分和时间不得逐字符断裂或 overflow；
- 保留点击比赛进入详情、刷新、分页和加载更多行为。

### VR2-4 积分榜

- 改为紧凑固定表头和连续表格行，列顺序对齐原型：排名、球队、场次、胜、平、负、进/失球、积分；
- 队徽使用图片回退，球队名一行省略，数字列固定宽度并右对齐/居中一致；
- 允许仅按排名区间增加无文字语义的浅绿/浅蓝行背景以复刻视觉分组，不得声称为真实欧战/降级资格；
- 点击球队继续进入原球队详情；空、错误、重试状态必须留在同一视觉外壳内；
- 360dp 可适度压缩列宽或横向滚动，但不得截掉积分列或造成文字重叠。

### VR2-5 球队榜与球员榜

- 将指标选择改为原型式左侧固定竖向栏，右侧为表头和排名行；不再使用首屏大号指标下拉框；
- 球队榜使用现有 `TeamRankType` 全部真实指标，选择后调用原 Controller；右侧显示排名、球队图片/名称和值；
- 球员榜使用现有 `PlayerRankType` 全部真实指标，选择后调用原 Controller；右侧显示排名、头像/姓名、球队和值；
- 指标栏宽度约占页面 18%～20%，选中项绿色、带右侧指示；右表约占 80%，列表滚动时表头和指标关系保持清楚；
- 球员头像和队徽可复用中性图片，不能以首字母作为正常态；长姓名、长球队名和带括号数值必须稳定省略而不挤压末列；
- 保留球员/球队详情跳转、分页、加载更多和失败重试。

### VR2-6 视觉规格与共用导航

- 以 750px 原型按实际页面宽度等比归一化，不把原型像素直接当 Flutter dp；
- 页面主体左右边距约 10～12dp，紧凑控件视觉高度约 32～38dp，主要圆角约 10～14dp；
- 字号层级按原型收紧：正文约 14～16sp，辅助信息约 11～13sp，比分可更大；
- 保持 VR1 已通过的白色悬浮胶囊底部导航、绿色“数据”选中态和安全区间距；
- 系统状态栏差异可豁免，应用内容区的模块顺序、比例、密度、颜色、圆角、图片和主要边缘目标偏差不超过约 4dp。

## 5. 契约与数据保护

- 复用现有 `FootballDataController`、`FootballRankingsController`、Repository、DTO、路由和状态模型；
- 复用 P1/P3 已验证的真实比赛、积分、球队榜和球员榜数据；主验收截图不得用 Widget fixture 代替正常 API 数据；
- 不增加后端字段，不修改数据库，不调整比赛或榜单排序；
- 不覆盖、重置或格式化工作区内既有 P1～VR1 改动；
- 如原型交互依赖当前契约不存在的持久化能力，只保留诚实的非交互视觉或记录差距，不得伪造成功状态；
- 图片只要求正常态“有图片”，允许复用，不要求每支球队和每名球员唯一素材。
