# 南看台客户端 UI 视觉基线

> 版本：v0.1  
> 当前阶段：F03.1  
> 文档定位：Flutter 客户端视觉 Token、共享组件和认证/首次设置页面视觉规则的唯一权威文档。  
> 不负责：API 契约、业务字段、完整架构树、Vue 管理后台视觉或 F04 业务实现。

## 1. 文档定位与适用范围

本基线适用于 `apps/mobile`。页面交互规则同时遵循 06，工程结构遵循 04；发生冲突时，本文件只对视觉 Token 与组件呈现负责。业务页面不得散落自定义品牌色、间距和圆角。

## 2. 产品视觉方向

产品 PDF 第 1 页提供首次登录与三项偏好选择示意，第 5 页提供首页卡片化方向。F03.1 将其转译为：高识别度蓝紫品牌主色、明显品牌顶区、极浅灰紫背景、白色主要内容卡片、轻量现代足球社区感、清楚的分步进度和稳定底部操作区。选中状态由背景、描边和图标共同表达，不只依赖小型 Radio/Checkbox。原型中的第三方商标、球员照片和 F04 首页内容不作为本轮资源或功能依据。

## 3. 颜色 Token

| Token | 值 | 用途 |
|---|---:|---|
| `brand` | `#5147E8` | 主按钮、焦点、进度与选中态 |
| `brandDark` | `#3328B8` | 品牌渐变、深色文字 |
| `brandSoft` | `#EAE8FF` | 轻选中背景与提示块 |
| `accent` | `#7B61FF` | 品牌渐变辅助色 |
| `page` | `#F7F6FC` | 页面背景 |
| `surface` | `#FFFFFF` | 内容卡片与固定操作区 |
| `surfaceMuted` | `#F0EFF7` | 次级容器与占位 |
| `ink` / `inkMuted` | `#1D1B2A` / `#6D6A7D` | 主/次文字 |
| `border` | `#E3E0ED` | 边框和分隔 |
| `success` / `error` / `warning` | `#168C5B` / `#C93C54` / `#B86812` | 语义状态 |

这些值为 F03.1 临时基准，后续只能在 Token 层统一调整。

## 4. 字体与文字层级

使用系统字体保证中文兼容。品牌/页面标题使用 700-800 字重；区块标题 700；正文保持 1.5 左右行高；辅助文字使用 `inkMuted`。不可用颜色代替标题层级，文本放大后核心动作仍须可用。

## 5. 间距系统

基础阶梯为 4、8、12、16、20、24、32、40。页面水平边距通常为 20，卡片内边距为 24，字段间距为 16，标题与说明间距为 8。禁止页面新增无依据的间距常量。

## 6. 圆角与边框

小型输入/标签 10-14，大卡片 20，品牌大容器 28。普通边框 1 px、选中边框 2 px；边框使用 `border`，选中使用 `brand`。

## 7. 阴影与层级

卡片优先依靠背景和边框分层，必要时使用统一轻阴影：黑紫 7% 透明度、24 模糊、向下 10。禁止重阴影和多层浮夸投影。

## 8. 页面背景与内容容器

Scaffold 使用 `page`。主要内容使用白色卡片，最大表单宽度 440；品牌头与卡片可轻微叠合。长列表占据剩余空间，底部操作区保持独立白色表面。

## 9. 按钮规范

主按钮蓝紫填充、最小高度 52、明确动词；次按钮品牌描边。Loading 时显示进度并禁用，Disabled 状态使用中性灰。危险动作不得伪装成主动作。

## 10. 输入框规范

输入框统一白底、14 圆角、聚焦 2 px 品牌描边；标签、前置图标和就近校验错误保持一致。认证表单需支持键盘滚动、密码显隐、合理提交动作和防重复提交。

## 11. AppBar/Header 规范

业务 AppBar 使用品牌色和白色前景。认证页使用明显的蓝紫渐变品牌头，包含南看台文字、足球线性图标、页面标题与一句简短副标题。

## 12. 选择卡片和 Chip 规范

选择卡片整块可点击，包含实体图、标题、辅助信息和尾部状态图标。选中态同时变化浅紫背景、2 px 品牌描边和勾选图标。Chip 仅用于数量/短标签，不作为复杂实体的唯一选择控件。

## 13. 球队 Logo、球员头像、普通图片占位规范

URL 可用时正常加载；URL 为空或失败时不得红屏。球队使用圆角盾牌容器与球队首字符/盾牌图标；球员使用圆形头像与姓名首字符/人物线性图标；普通图片使用统一浅灰背景和图片/足球线性图标。同一实体的背景色由稳定 ID/名称计算，不使用随机色。Widget 接收已解析 URL，不拼接 Base URL，不展示图片异常堆栈，并提供语义标签。本轮不下载或写死真实图片。

## 14. Loading/Empty/Error/Retry/Disabled/Success

所有状态使用统一图标、标题、说明与可选重试按钮。Loading 不制造布局跳动；Empty 不表现为错误；Error 不展示 trace/堆栈；Retry 使用明确动词；Disabled 同时在视觉和交互上不可提交；Success 使用绿色语义而不只依赖绿色。

## 15. 登录页规范

品牌头 + 白色表单卡片；展示南看台与足球社区副标题。用户名、密码、显隐、就近错误、品牌主按钮、注册入口完整保留。小屏与键盘弹起时允许整体滚动，不增加第三方登录。

## 16. 注册页规范

与登录页共享品牌头、卡片、字段和按钮语言；字段依次为用户名、手机号、密码、确认密码。注册成功后的既有路由行为不变，错误就近显示，重复提交被禁用，返回登录入口清晰。

## 17. Onboarding 分步流程规范

共三步：主队单选、关注球队多选、关注球员多选。顶部展示 1/3 至 3/3 的分段进度；各步可本地搜索。底部操作区稳定并使用 SafeArea：第一步仅下一步且未选主队禁用，第二步上一步/下一步，第三步上一步/完成首次设置。返回上一步不丢选择，仅第三步调用原有 submit。主队自动关注与提交契约保持 F03 实现。

## 18. F03 临时完成页规范

使用统一品牌头、白卡、成功状态、非敏感用户名/昵称、明确“F04 主框架与首页待开发”和退出登录。不得展示假新闻、假比赛、假统计或底部主导航。

## 19. Pixel 8 / Android 手机验收标准

在 Pixel 8、Android API 36 参考尺寸下检查：无黄黑 overflow、键盘不遮挡提交、长列表与底部操作区不冲突、系统返回键逐步返回、横向无异常滚动、文字放大后主要动作仍可达、图片失败稳定。自动测试不能代替真机/模拟器人工观察。

## 20. F04 首页与主框架继承规则

F04 必须继续使用本文件的颜色、字体、间距、圆角、状态组件和实体占位策略。首页卡片流可依据第 5 页的轻量卡片方向扩展，但业务卡片、底部导航和真实数据必须由 F04 单独实现与验收。

## 21. 暂不确定项

最终品牌 Logo/字体、深色模式、正式动效、普通内容图片比例、无障碍对比度的产品级复核、iOS 视觉差异与 Golden Test 策略尚未确认。F03.1 不通过猜测补齐这些内容。
