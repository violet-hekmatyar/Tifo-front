# VR4 球队详情一比一视觉复刻执行计划

最终验收：Plan/验收模型  
固定真实球队：`13000000000000012`（尤文图斯）

## 1. 唯一目标与范围

本阶段只完成球队详情模块，使当前源码 APK 在真实 API 下对齐以下 7 张原型的页面结构、模块顺序、比例、信息密度和交互状态：

- `球队详情-总览.png`
- `球队详情-帖子.png`
- `球队详情-球员.png`
- `球队详情-数据.png`
- `球队详情-赛程.png`
- `球队详情-数据选择.png`
- `球队详情-榜单查看全部.png`

不得扩展到球员详情视觉返工、首页或比赛详情重构、内容发布、聊天登录能力、完整淘汰树、后端新接口或数据库补数。只有发现上述 7 个页面确因既有契约缺失而无法成立时，才暂停并形成精确的后端需求说明，不得自行扩大后端范围。

## 2. 共用验收基线

- 所有正式截图使用球队 `13000000000000012` 和真实 API，不以 fixture、mock 或旧截图代替。
- 页面正常态必须显示可访问的球队 Logo、内容封面和球员图片；允许多名球员复用同一张图片，不接受首字母、空白块或破图作为正式证据。
- 复用现有路由、组件和 API 契约，不引入平行数据源，不硬编码榜单行、赛程、统计或球员。
- 必须覆盖标准 Pixel 8、360dp 和系统字体 140%；文字可合理省略，但不得溢出、重叠或隐藏关键操作。
- 加载、空、失败和未登录状态必须可恢复；不得为了截图删除容错逻辑。

## 3. VR4-M0：契约与数据映射

开始 UI 修改前先完成以下窄范围核验：

1. 验证球队基础信息、总览、球员、统计、荣誉、赛程和动态接口均能以目标球队返回真实数据。
2. 补齐 Flutter 模型对既有总览字段 `competitionStandings`、`leaderboards` 的解析；字段名称和语义以当前后端响应为准，不修改 API 契约。
3. 赛季和赛事选择项只能从真实响应推导；数据切换后，旧请求结果不得覆盖新选择。
4. “加为主队”必须使用既有 `PUT /api/app/users/me/profile` 的 `mainTeamId` 字段，并通过用户摘要回读验证。未登录时走现有登录引导；不得把“关注球队”接口伪装成“加为主队”。
5. 若现有 Logo 或球员图片不可匿名/带认证访问，优先使用 P1 已验证媒体和现有图片组件回退；本阶段不新增数据库脚本。

完成门槛：真实 API 的字段映射、鉴权边界和各页数据来源记录在执行报告中；无自创字段和静态演示行。

## 4. VR4-M1：沉浸式球队头部与五页导航

- 将通用绿色 AppBar/白卡头部改为原型的深酒红球队主题头图：返回按钮、真实队徽、球队名、真实地区/联赛信息、淡化队徽水印及“加为主队/已是主队”按钮。
- 不展示后端没有依据的球队身价；可用真实城市、主场或联赛信息保持原型层级。
- 总览、帖子、球员、数据、赛程五个标签必须为同一行纯文字导航，当前项使用短下划线，不使用现有图标标签。
- 头部与标签在页面切换时保持一致，返回、主队按钮和标签操作区域均可点击。

完成门槛：五个页面共享同一头部骨架，标准宽度、360dp 和 140% 字体下不换成两行导航、不溢出、不遮挡。

## 5. VR4-M2：球队总览完整页面

严格按原型组织纵向内容：

1. 下一场比赛卡：时间、赛事、主客队 Logo/名称和赛前状态，点击进入真实比赛详情。
2. 多赛事积分区：使用 `competitionStandings`，显示赛事标题、球队行与查看入口；不得使用普通键值卡代替。
3. 最新资讯：双列封面卡，包含内容类型、标题和必要元信息，点击进入真实内容详情。
4. 球员榜：射手榜和助攻榜并列展示，使用 `leaderboards`，均提供“查看全部”。
5. 基本信息：成立年份、城市、主场、主教练等仅展示真实字段。
6. 荣誉：使用真实荣誉数据，按原型形成奖杯/赛事层级，空数据有明确空态。

完成门槛：总览首屏与长页下半部分各有正式证据；模块顺序、双列密度和原型一致，所有可点击入口可达。

## 6. VR4-M3：帖子与球员

### 帖子

- 改为原型双列瀑布/网格内容卡，真实封面、标题、作者/互动信息层级完整。
- 保留分页、下拉刷新、加载尾部、空态和失败重试；去除明显测试文案，不通过客户端伪造内容。
- 卡片点击进入现有内容详情。

### 球员

- 按门将、后卫、中场、前锋等真实位置分组，组内使用原型的双列金黄色大图球员卡。
- 卡片显示球员图片、号码、姓名、年龄/国籍及现有数据可支持的关键统计；没有字段的项目不虚构。
- 点击进入现有球员详情。图片允许复用，但正式证据中不得出现首字母或空白头像。

完成门槛：帖子和球员各有完整首屏正式截图；球员列表覆盖所有真实返回球员且分组正确，无卡片裁切或横向溢出。

## 7. VR4-M4：数据、选择层与榜单全部

- 数据页顶部实现真实赛季/赛事选择器和“总计/场均”分段控件；场均值仅能由真实总量和出场数安全计算，零场次不得除零。
- 将统计按进攻、组织、防守、纪律等业务类别排成原型的分组卡片，保持紧凑数值层级。
- `球队详情-数据选择.png` 使用底部弹层复刻：按真实赛季分组赛事，当前项明确选中，选择后关闭并刷新对应数据。
- `球队详情-榜单查看全部.png` 实现明确的独立页或全屏态，含返回、赛季/指标选择与完整真实球员排行；不得仅放大总览小卡或伪造榜单行。
- 快速连续切换时必须丢弃过期响应，加载/空/失败状态不闪回旧选择。

完成门槛：数据正常态、选择层和榜单全部态各有正式截图并与对应原型逐图对照；交互测试覆盖切换与返回。
