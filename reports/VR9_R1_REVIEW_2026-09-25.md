## 2. 阻塞视觉通过的发现

### P1：资料头内部结构仍与原型不同

原型将头像、昵称和三个统计项组合在同一资料带中，统计项位于昵称下方且整体从头像右侧开始。当前 APK 增加了 `@username`/关系提示，并把三个统计项展开为下一行全宽三等分，第一项中心明显移到头像左侧。虽然头部总高度约 285dp，仍在 268dp 的 ±8% 边界附近，但内部横向层级不一致，不能以总高度合格替代结构合格。

### P1：头部主色仍明显偏亮绿

在无文字的对应顶部区域抽样，原型约为 `#14393A`～`#153A3C` 的深青色，当前 APK 约为 `#09734A`～`#0B744A` 的亮绿色。当前实现直接使用全局 `AppColors.brandDark` 叠加，未复刻原型的局部深青色蒙层。

### P1：看台卡片比例和 360dp 排版未收口

当前三张看台卡的高度、左侧圆形图标和预览节点均明显大于原型；360dp 证据中“我关注的球队”发生两行断行，而原型在接近宽度下保持单行紧凑标题。无 overflow 只能证明健壮性，不能证明视觉对齐。

### P1：关系按钮尺寸明显超出原型

当前代码为所有关系按钮设置最小 `92×40dp`；原型中普通关系按钮约 `56×26dp`，四字状态也只是按内容略微扩展。当前按钮宽高、圆角和文字占比明显过大，挤压简介可见宽度，关注和粉丝两张图均未达到紧凑行结构。

### P1：发布卡仍不是原型式个人主页瀑布流

当前内容卡保留首页网格的 `帖子` 角标、统一约 1.28 的媒体比例、较粗标题和较大边距；原型个人主页卡没有该角标，媒体高度呈更紧凑的瀑布节奏。R1 已补足数量，但卡片视觉结构和密度仍有显著差异。

### P1：计划要求的几何证据和测试没有真正落地

- `VISUAL_COMPARISON.md` 只有文字观察，没有“原型 dp / R1 dp / 偏差 / 是否在 ±8%”实测表。
- 头部测试允许 `260～430dp`，远宽于 268dp 的 ±8% 目标范围。
- 关系测试只挂载 `UserListView`，没有覆盖完整 `UserRelationsPage` 的返回栏、Tab、搜索框与首行组合锚点。
- 搜索框测试只断言高度 `<70dp`，没有证明约 40dp；未断言按钮尺寸、首行顶边和 360dp 看台标题单行。

因此“56 项测试通过”真实有效，但不能证明本阶段的严格几何门禁已经通过。

### P2：数据幂等证据与计划记录不一致

执行记录写明“Seed 一次、Validator 连续两次”，而 R1 计划要求 Seed 连续执行两次。现有脚本设计基本可重复，但尚缺同一环境的 Seed 双跑前后行数证据。Validator 也应补充正文块归属、看台目标对象身份和本轮保留关系所有权的强制失败检查。

## 3. 复验决定

1. VR9-R1 的功能、图片、内容数据、关系数据、56 项测试和当前 API 联调结果全部保留。
2. 五张用户中心原型继续保持“不通过”，不计入严格视觉完成数。
3. 只开放 `VR9_R2_FINAL_PIXEL_REPAIR_PLAN.md`，处理资料头内部网格、局部配色、看台卡、个人主页内容卡、关系按钮及量化证据。
4. VR9-R2 未经 Plan 模型逐图复验前，不得进入 VR10。
